# 文本向量化 Embedding 与相似度

## 什么是 Embedding

Embedding（嵌入）把一段文本映射成一个固定长度的浮点向量，可以理解为这段文本在语义空间里的坐标。嵌入模型在海量语料上训练，目标是让语义相近的文本向量距离也近，因此它支持语义匹配：用户问“咋用”，也能和写着“使用方法”的片段对上，这是关键词字面匹配做不到的。

## 一个 chunk 一个向量，不是每个 token 一个向量

模型内部确实逐 token 产生隐藏向量，但经过池化（pooling）后，整段 chunk 只输出一个向量。RAG 离线入库时是对每个分好的 chunk 算一个向量；在线问答时只对用户问题算一次向量，chunk 向量在入库时已经算好，不用重复计算。

## 向量维度

维度是向量的长度，由嵌入模型决定，例如阿里云 DashScope 的 text-embedding-v3 可输出 512、1024 维等，本项目统一使用 512 维。维度越高表达能力越强但存储和计算成本越高；一个集合里所有向量维度必须一致。

## 余弦相似度

检索时计算问题向量与每个 chunk 向量的余弦相似度，即两个向量方向的一致程度，取值 -1 到 1，越接近 1 越相关，按分数从高到低取 Top-K。相比欧氏距离，余弦相似度只看方向、不受向量模长影响，更适合文本语义匹配。Milvus 建集合时度量方式选 COSINE。

## 语义匹配的边界与批量降本

Embedding 擅长同义、近义、跨语言的语义匹配，但对生僻专有名词、编号、错误拼写不敏感，这正是需要关键词检索（BM25）补位的地方。调用嵌入接口按 token 计费，入库时把多个文本组成批次一次性请求（批量 embedding），可以显著减少请求次数、降低成本和耗时。
