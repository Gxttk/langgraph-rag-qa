# Prompt 设计与 temperature 参数

## Prompt 的基本结构

一个清晰的提示词通常包含：角色（你是谁）、任务（要做什么）、上下文（检索到的资料或历史）、约束（只依据资料、不知道就说未提及）、输出格式（JSON / 分点 / 带引用编号）。RAG 里要明确要求模型“只根据给定资料回答并标注来源，资料不足就回答未提及”，这是抑制幻觉的关键。

## temperature 控制什么

temperature 控制采样的随机性，本质是在调整下一个 token 概率分布的尖锐程度：

- 温度越低（如 0~0.2），分布越尖锐，模型越倾向选高概率词，输出稳定、可复现、收敛，适合抽取、分类、改写、判级、结构化输出这类要求确定答案的任务。
- 温度越高，分布越平，低概率词更容易被选中，输出越发散、有创造性，但也更容易跑偏或不稳定，适合头脑风暴、文案创作。
- temperature=0 时近似贪心解码，同样输入基本得到同样输出。

## 分节点设置温度

一个图里不同节点对随机性的需求不同，应分别设置而不是全局一个值。本项目按节点取不同温度：问题补全 0.1、Rerank 精排 0.0、检索质量评估 0.1、最终回答 0.2、查询改写 0.5（适度发散以得到多样的检索词）。判级、排序这类要稳定的节点用接近 0 的温度，需要拓展的改写节点稍高。

## top_p 与其他注意点

top_p 是另一种采样控制（核采样），它和 temperature 作用方向类似，一般以调一个为主，不建议同时把两者都调得很激进。要求 JSON 等结构化输出时可配合结构化输出/JSON 模式，并对解析失败做兜底（返回默认判定而不是让流程崩溃）。
